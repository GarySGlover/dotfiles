*** I think I could define these scripts in emacs lisp and use emacs instead of rofi/wofi. My emacs runs as a daemon, so all I would need for the wofi part is to know how open a new frame that does only the completing-read and doesn't show any other buffers.

Absolutely—you can use Emacs as your profile menu! Here’s a concise solution:

*Elisp Implementation Outline*

1. *Define your monitor profile scripts:*
Store a list associating profile names with shell scripts or niri commands.

2. *Prompt for selection with completing-read:*
Open a new frame, run completing-read to let you pick a profile.

3. *Run the script/cmd in the background:*
Invoke shell-command or start-process accordingly.

4. *Handle dedicated UI frame:*
- Create a new frame with only the completion buffer.
- Close the frame after selection.

*Sample Implementation*
#+begin_src emacs-lisp
(defun my/monitor-profiles ()
  ;; Alist: (name . script)
  '(("Office Dual External"
     . "~/bin/monitor-office.sh")
    ("Home Laptop + TV"
     . "~/bin/monitor-home.sh")
    ("Single Laptop"
     . "~/bin/monitor-laptop.sh")))

(defun my/select-monitor-profile ()
  (interactive)
  (let* ((frame (make-frame '((name . "Monitor Profile Selector")
                             (width . 50)
                             (height . 5)
                             (minibuffer . only))))
         (profile (completing-read "Select monitor profile: "
                                  (mapcar #'car (my/monitor-profiles))))
         (script (cdr (assoc profile (my/monitor-profiles)))))
    (when script
      (message "Script"))
    (delete-frame frame)))

;; Optional: bind to a global key, or run via terminal (emacsclient)
#+end_src

*How to Use*
- Call =my/select-monitor-profile= via =emacsclient= or a keybinding.
- It opens a temporary frame; lets you pick; runs the script; deletes the frame (no buffer clutter).

*Finetuning*
- You can hide other buffers by setting frame parameters and/or using a dedicated workspace.
- For more control, ensure only the minibuffer is active in the frame.

*Launching via Emacsclient*
- From the shell: =emacsclient -c -e '(my/select-monitor-profile)'=

*Summary:*
Yes, you can build a clean, minimal monitor profile launcher in Emacs using a new frame and completing-read. No need for wofi/rofi!

*Solution:*
- Tell =emacsclient= to /not/ create an initial frame, and let your function create the /only/ one needed.

*Ways to achieve this:*

*** 1. Use =emacsclient= without =-c=, but with =--eval=
If your Emacs server is already running, from the terminal:
#+begin_src sh
emacsclient --eval '(my/select-monitor-profile)'
#+end_src
This will NOT open a new frame, just runs the code. Your code creates the selector frame.

If you want it to show up on your desktop (not just in the Emacs running in a TTY), make sure your daemon is running under GUI (X11/Wayland), or set up =server-window= correctly.

*** 2. Hide the initial client frame, or reuse it

You can slightly adapt your code to /reuse/ the current frame (if pop-up):
If called from a GUI client, use the current frame as the input frame. If in terminal or via emacsclient without frame, make a new one.

You could conditionally use =selected-frame= if it's not a TTY and doesn't already have a minibuffer:
#+begin_src elisp
(defun my/select-monitor-profile ()
  (interactive)
  (let* ((existing-frame (and (display-graphic-p) (not (window-minibuffer-p (selected-window))) (selected-frame)))
         (frame (or existing-frame

                                  (width . 50)
                                  (height . 5)

    (when script
      (start-process-shell-command "monitor-profile" nil script))
    (unless existing-frame (delete-frame frame))))
#+end_src
This reuses a frame if possible, otherwise creates/deletes one as needed.
